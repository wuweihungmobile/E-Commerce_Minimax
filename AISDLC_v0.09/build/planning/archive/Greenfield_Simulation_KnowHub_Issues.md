# Greenfield SOP 問題清單 - KnowHub 模擬

**建立日期**: 2026-03-23
**模擬系統**: KnowHub（專業內容發布 CMS + 知識管理 KMS 融合系統）
**技術棧**: React(Next.js) + Spring Boot + PostgreSQL + Elasticsearch
**平台**: Web + Android + macOS (Type A Hybrid)
**目標文件**: AISDLC_v0.09/scenarios/greenfield/SOP.md

## 問題清單

### 🔴 Critical（3 項）

#### #1 CMS/KMS 領域業務規則缺失
- **所在 Stage**: Stage 2（需求深潛）
- **問題**: 「產業領域業務規則提示表」缺少「媒體/出版/內容管理」和「知識管理/Wiki」兩大領域。內容審核流程、排程發布、版本管理、全文搜尋等 CMS/KMS 特有業務規則完全無引導。
- **影響**: 需求分析階段遺漏關鍵業務規則

#### #2 全文搜尋引擎選型指引缺失
- **所在 Stage**: Stage 3（技術選型）
- **問題**: 技術棧評估表完全缺少搜尋引擎選型（Elasticsearch vs Meilisearch vs PostgreSQL FTS vs Algolia）。對 KMS 而言全文搜尋是核心功能，需專項選型評估。
- **影響**: 技術決策缺乏系統化指引

#### #3 內容審核工作流狀態機設計與 Epic 拆解範例缺失
- **所在 Stage**: Stage 5-7（架構設計、Sprint 規劃）
- **問題**: 缺少「編輯型工作流」的狀態機設計指引（草稿→審核→排程→發布→歸檔）、審核駁回迴圈、多角色審核權限。Stage 6 無內容審核 Epic 拆解範例。Stage 7 無複雜狀態機 Sprint 拆分方法論。
- **影響**: 核心業務流程無設計參考，開發拆分困難

---

### 🟠 High（10 項）

#### #4 富文本編輯器選型指引完全缺失
- **所在 Stage**: Stage 3（技術選型）
- **問題**: 技術棧評估表缺少「前端富文本編輯器」選型（TipTap / ProseMirror / Slate / Quill）。CMS 的核心功能是文章編輯，編輯器選型影響深遠。
- **影響**: 前端技術決策無依據

#### #5 內容編輯相關 NFR 需求引導缺失
- **所在 Stage**: Stage 2（需求深潛）
- **問題**: NFR 引導問題缺少：富文本編輯器需求（協作編輯、媒體嵌入）、內容資產存儲需求（檔案大小限制、自動壓縮）、搜尋引擎優化 NFR（Meta 標籤、Sitemap）、內容性能 NFR。
- **影響**: 非功能性需求遺漏

#### #6 內容版本管理與版本比對設計指引缺失
- **所在 Stage**: Stage 5（架構設計）
- **問題**: 缺少「內容版本鏈」資料模型設計（完整副本 vs 變更日誌 vs 混合）、版本 diff 算法指引、版本保留策略、版本審計追蹤。KMS 的版本追蹤是核心功能。
- **影響**: 版本管理功能無設計參考

#### #7 多渠道內容發布架構設計指引缺失
- **所在 Stage**: Stage 5（架構設計）
- **問題**: 缺少「同一內容多平台同步發布」的設計模式、多渠道發布狀態機、平台差異化欄位 API 設計、發布排隊與重試機制、發布失敗降級處理。
- **影響**: 多渠道發布架構無參考

#### #8 搜尋索引同步與一致性策略缺失
- **所在 Stage**: Stage 8-10（CI/CD、文檔一致性、測試）
- **問題**: CI/CD 未涵蓋搜尋索引部署策略、文檔一致性檢查未包含 DB↔索引一致性驗證、測試策略未列出索引同步延遲測試。缺少 CDC/MQ 同步方案指引。
- **影響**: 搜尋功能品質無保障

#### #9 CDN 快取管理與清除策略缺失
- **所在 Stage**: Stage 8, 11（CI/CD、部署）
- **問題**: CI/CD 未涵蓋 CDN 配置和快取策略、部署步驟未包含快取清除（Cache Invalidation）、回滾時如何處理 CDN 快取未定義。缺少快取預熱策略。
- **影響**: 發布後用戶可能看到舊內容

#### #10 排程發布端到端測試策略缺失
- **所在 Stage**: Stage 10（測試）
- **問題**: 測試策略未涵蓋排程任務測試方法、時區相關測試、分散式排程唯一性測試、排程失敗恢復測試。CMS 的定時發布是核心功能。
- **影響**: 排程功能品質無驗證手段

#### #11 搜尋索引回滾策略缺失
- **所在 Stage**: Stage 11（部署與回滾）
- **問題**: 回滾策略未涵蓋 Elasticsearch 索引回滾（索引無法像應用版本輕鬆回滾）。缺少索引別名切換方案、索引備份復原流程、索引重建耗時估算。
- **影響**: 搜尋功能故障恢復無方案

#### #12 媒體存儲與 CDN 選型指引缺失
- **所在 Stage**: Stage 3（技術選型）
- **問題**: 缺少雲端存儲方案選型（S3 / GCS / MinIO）、CDN 選型指引、媒體處理引擎選型（FFmpeg / ImageMagick）、媒體上傳流程 API 設計指引。
- **影響**: 媒體管理技術決策無依據

#### #13 複雜業務規則 Sprint 拆分指引缺失
- **所在 Stage**: Stage 7（Sprint 規劃）
- **問題**: 缺少「複雜工作流邏輯」的 Sprint 拆分方法論、循環依賴識別、業務規則優先級排序矩陣。審核流程涉及多級審核和角色權限的複雜依賴。
- **影響**: 開發規劃可能不合理

---

### 🟡 Medium（10 項）

#### #14 SEO 最佳化設計與一致性檢查指引缺失
- **所在 Stage**: Stage 5, 9（架構設計、文檔一致性）
- **問題**: 缺少 SEO 資料模型設計（Meta title/description/keywords/canonical URL）、URL Slug 生成與去重策略、結構化資料（JSON-LD）、Sitemap 自動生成。Stage 9 未包含 SEO 元資料一致性檢查。
- **影響**: 內容平台的 SEO 品質無保障

#### #15 細粒度 RBAC 與權限管理設計指引缺失
- **所在 Stage**: Stage 5（架構設計）
- **問題**: 缺少「內容管理系統的 RBAC 設計指引」，包括：欄位級別權限、資源所有權 vs 角色權限的設計決策、審核權限分級。
- **影響**: 權限設計可能過於粗糙

#### #16 權限控制綜合測試策略缺失
- **所在 Stage**: Stage 10（測試）
- **問題**: 缺少權限測試矩陣（所有角色組合）、跨平台權限一致性測試、權限快取失效測試、權限越級安全測試。
- **影響**: 安全性驗證不完整

#### #17 富文本與媒體儲存測試策略缺失
- **所在 Stage**: Stage 10（測試）
- **問題**: 缺少媒體上傳與儲存測試（S3/MinIO）、富文本到 HTML 轉換安全測試（XSS 防護）、媒體 CDN 加速測試、跨平台媒體相容性測試。
- **影響**: 內容編輯功能品質無保障

#### #18 知識圖譜相關設計指引缺失
- **所在 Stage**: Stage 5（架構設計）
- **問題**: 缺少知識圖譜資料模型設計、圖資料庫 vs 關聯式資料庫選型指引、知識推薦算法設計、知識關係類型定義。
- **影響**: KMS 進階功能無設計參考

#### #19 內容版本回退功能測試策略缺失
- **所在 Stage**: Stage 10（測試）
- **問題**: 缺少版本回退端到端測試場景、發布版本回退 vs 編輯草稿回退區分、版本回退後 SEO 影響、版本回退後搜尋索引一致性。
- **影響**: 版本控制功能驗證不完整

#### #20 跨平台內容工作流端到端測試缺失
- **所在 Stage**: Stage 10（測試）
- **問題**: 缺少「編輯在 Web 發起審核→審核人在 Mobile 批准→所有平台同時發布」的跨平台工作流測試。缺少推播通知跨平台測試、離線編輯同步測試。
- **影響**: 多平台工作流一致性無驗證

#### #21 資料庫遷移版本管理與測試指引缺失
- **所在 Stage**: Stage 8, 10（CI/CD、測試）
- **問題**: DB 遷移策略（Flyway/Liquibase）提及但未展開。缺少遷移前測試方法、大表遷移注意事項、遷移驗證清單、遷移失敗回滾時間估算。
- **影響**: 發版安全性風險

#### #22 評論與審核意見子系統設計指引缺失
- **所在 Stage**: Stage 6（User Story 拆解）
- **問題**: 內容審核涉及「評論系統」（評論與版本綁定、評論線程、評論解決狀態、評論通知），但 SOP 未提供評論子系統的 API 和資料模型設計範例。
- **影響**: 審核流程的評論功能缺乏設計參考

#### #23 A/B 測試與漸進式發布配置指引缺失
- **所在 Stage**: Stage 11（部署）
- **問題**: Canary Release 有概念但缺少 Feature Flag 和 A/B 測試配置細節。內容平台常需測試新功能效果（如推薦算法、編輯器功能）。
- **影響**: 發布策略不夠精細

---

### 🟢 Low（2 項）

#### #24 國際化與多語言內容測試指引缺失
- **所在 Stage**: Stage 10（測試）
- **問題**: 若 KnowHub 支援多語言，缺少多語言內容搜尋測試（繁簡體匹配）、RTL 語言支援測試。
- **影響**: 未來擴展時缺乏指引

#### #25 合規性檢查（GDPR 等）CI/CD 整合缺失
- **所在 Stage**: Stage 8（CI/CD）
- **問題**: 若涉及用戶個人資料（編輯歷史、審核意見），CI/CD 未整合合規性檢查流程和審計日誌部署配置。
- **影響**: 法規合規風險（視需求而定）
