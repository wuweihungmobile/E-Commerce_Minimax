## 📌 目的 (Purpose)

本文檔定義專案的 **MVP (Minimum Viable Product, 最小可行產品)** 範圍，協助團隊：

1. **聚焦核心價值**：識別最關鍵的功能，快速驗證產品假設
2. **優先順序排序**：使用 RICE 分數與 Kano 模型科學排序功能
3. **分階段發布**：將功能劃分為 Phase 1 (MVP)、Phase 2、Phase 3
4. **控制成本與時程**：避免過度設計，加速產品上市時間

## 🏆 第二部分：功能優先順序排序 (Feature Prioritization)

### 2.1 RICE 評分方法 (RICE Scoring Model)

**RICE** = **Reach** × **Impact** × **Confidence** / **Effort**

| 因子 | 定義 | 評分標準 |
|-----|-----|---------|
| **Reach** (觸及範圍) | 此功能在特定時間內會影響多少使用者？ | 人數 (例: 100 人/季度 = 100) |
| **Impact** (影響力) | 對單一使用者的影響程度？ | 3 = 巨大, 2 = 高, 1 = 中, 0.5 = 低, 0.25 = 微小 |
| **Confidence** (信心度) | 對此評估的信心程度？ | 100% = 高信心, 80% = 中信心, 50% = 低信心 |
| **Effort** (開發工作量) | 需要多少人/月？ | 人月數 (例: 1 人工作 2 週 = 0.5 人月) |

**計算公式**：
```
RICE 分數 = (Reach × Impact × Confidence) / Effort
```

**範例計算 (MoneyTracker 的「快速記帳」功能)**：
- **Reach**: 800 人/季度 (假設 80% 使用者會使用此功能)
- **Impact**: 3 (巨大影響，核心功能)
- **Confidence**: 100% (高信心)
- **Effort**: 1 人月

```
RICE = (800 × 3 × 1.0) / 1 = 2,400
```

### 2.3 Kano 模型分類 (Kano Model Classification)

**Kano 模型**將功能分為 5 類：

| 類別 | 英文名稱 | 定義 | 開發優先順序 |
|-----|---------|-----|-------------|
| **必須型** | Must-be | 使用者認為理所當然，沒有會不滿，有了也不會特別高興 | ✅ **Phase 1 (MVP)** |
| **期望型** | One-dimensional | 功能越好，使用者滿意度越高 | ✅ **Phase 1 或 Phase 2** |
| **魅力型** | Attractive | 使用者沒想到的驚喜功能，有了會很開心 | ⏸ **Phase 2 或 Phase 3** |
| **無差異型** | Indifferent | 有沒有都無所謂 | ❌ **不開發** |
| **反向型** | Reverse | 有了反而讓使用者不滿 | ❌ **不開發** |

### A. RICE 評分詳細計算過程

**功能**: F-001 快速記帳

| 因子 | 計算邏輯 | 數值 |
|-----|---------|-----|

| **Effort** | 1 名開發者工作 1 個月 | 1.0 人月 |
| **RICE** | (800 × 3 × 1.0) / 1.0 | **2,400** |

### B. Kano 問卷範例

**問題格式**：

**正向問題**：如果 [功能] 存在，你的感受是？
- 😍 我很喜歡
- 😊 我會期待這樣
- 😐 我沒感覺
- 😕 我可以忍受
- 😡 我不喜歡

**反向問題**：如果 [功能] 不存在，你的感受是？
- 😍 我很喜歡
- 😊 我會期待這樣
- 😐 我沒感覺
- 😕 我可以忍受
- 😡 我不喜歡

**範例**: F-007 雲端備份與同步

| 正向問題回答 | 反向問題回答 | Kano 分類 |
|------------|------------|----------|

| 😐 我沒感覺 | 😐 我沒感覺 | **無差異型** (Indifferent) |
