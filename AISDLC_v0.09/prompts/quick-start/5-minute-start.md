## 🎯 快速體驗路徑

### 第 1 分鐘：初始化框架

```
請載入 AISDLC v0.02 框架。

執行指令：
請閱讀並載入 /AISDLC_v0.02/AISDLC_INIT.md

我想體驗 AISDLC 的核心功能。
```

### 第 2 分鐘：選擇情境

三選一快速體驗：

#### 選項 A：體驗 Greenfield（全新專案開發）
```
我想開發一個簡單的待辦事項 Web App。

功能需求：
- 用戶可以新增、編輯、刪除待辦事項
- 待辦事項可以標記完成/未完成
- 需要用戶登入功能

請使用 Greenfield 情境，快速執行需求提取和技術選型階段。
```

#### 選項 B：體驗 Brownfield（既有系統維護）
```
我有一個既有的用戶管理系統，需要新增「忘記密碼」功能。

請使用 Brownfield 情境：
1. 快速分析既有代碼結構
2. 評估新增功能的影響範圍
3. 提供實作建議
```

#### 選項 C：體驗 Refactoring（代碼重構）
```
我有一個函數過於複雜，需要重構。

函數資訊：
- 圈複雜度：25（過高）
- 功能：處理用戶訂單邏輯
- 問題：難以理解和維護

請使用 Refactoring 情境，提供重構建議。
```

### 第 3-4 分鐘：執行 Workflow

**框架會自動**：
1. ✅ 載入對應情境的 SOP
2. ✅ 啟動相關 Agents（SA/PM/SD/等）
3. ✅ 執行情境專用 Workflow
4. ✅ 產出初步文檔（PRD/FRD/技術建議）

**你只需要**：
- 在 🔴 確認點回應「是」或提供補充資訊
- 選擇 Agents 提供的編號選項（Numbered Options Protocol）

### 第 5 分鐘：查看成果

**你會得到**：
- 📄 初步需求文檔（PRD/FRD）
- 🏗️ 技術方案建議（技術棧/架構設計）
- ✅ 下一步行動清單
- 🔗 相關模板與資源連結

## ❓ 常見問題

### Q1: 我需要準備什麼材料？
**A**: 最少只需要：
- 簡單的需求描述（文字/截圖/混合格式）
- （可選）既有代碼路徑（若是 Brownfield/Refactoring）

### Q2: 每個步驟都要手動確認嗎？
**A**: 只有關鍵決策點需要確認（標註 🔴），其他自動執行。

### Q3: 產出的文檔可以修改嗎？
**A**: 當然可以！AISDLC 產出的文檔都是模板化的 Markdown，可以自由編輯。

### Q4: 如果中途中斷，可以繼續嗎？
**A**: 可以！AISDLC 有 Checkpoint 機制，可以從中斷點恢復執行。

### Q5: 支援哪些平台？
**A**: 全平台支援（Web/iOS/Android/Mobile/Backend），並有平台特化 Agents。
