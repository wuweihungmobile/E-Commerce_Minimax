## 4. Sprint 13 User Stories

### US-001: 知識庫文章進階管理

**描述**:
作為 StoreOwner，我想要對知識庫文章進行版本控制和發布排程，以便更好地管理內容發布流程。

**驗收標準**:
- [ ] AC-001: 可以查看文章的版本歷史
- [ ] AC-002: 可以設定文章的發布時間（排程發布）
- [ ] AC-003: 可以恢復到之前的文章版本

**技術備註**:
- 需要新增文章版本相關欄位或獨立版本表
- 排程發布需要 Scheduler 或 Cron Job

**依賴**:
- M18 知識管理 Phase 2-A 已完成

---

### US-002: 知識庫搜尋增強

**描述**:
作為 Guest/Buyer，我希望能夠快速搜尋知識庫文章，找到相關的幫助資訊。

**驗收標準**:
- [ ] AC-001: 支援關鍵字全文搜尋
- [ ] AC-002: 支援標籤過濾
- [ ] AC-003: 搜尋結果高亮顯示關鍵字

**技術備註**:
- 可考慮使用資料庫 LIKE 或未來遷移到 ElasticSearch
- 前端搜尋輸入防抖動處理

**依賴**:
- M18 知識管理 Phase 2-A 已完成

---

### US-003: 評價系統資料模型建立

**描述**:
作為系統，我需要建立評價系統的資料模型，以便後續功能開發。

**驗收標準**:
- [ ] AC-001: 建立 reviews 表（商品評價）
- [ ] AC-002: 建立 booking_reviews 表（民宿預訂評價）
- [ ] AC-003: 資料表包含必要欄位並建立正確的索引

**技術備註**:
- 評價星級 1-5 分
- 需要關聯用戶、商品/預訂
- 考慮圖片多媒體欄位（Phase 2+）

**依賴**:
- 無，直接基於現有架構

---

### US-004: 評價 CRUD API

**描述**:
作為 Buyer，我希望能夠對已完成的訂單/預訂進行評價，作為 Host/Seller，我希望能夠回覆買家的評價。

**驗收標準**:
- [ ] AC-001: 買家可以對已完成訂單提交評價
- [ ] AC-002: 買家可以對已完成預訂提交評價
- [ ] AC-003: 賣家/房東可以回覆評價
- [ ] AC-004: 查詢評價列表（商品評價、店家評價）

**技術備註**:
- 評價後不可修改（Immutable）
- 回覆可編輯
- 防止重複評價（每個訂單/預訂只能評價一次）

**依賴**:
- US-003 評價系統資料模型已完成
