## 4. 詳細發現

### 🔴 發現 #1: 知識管理模組缺失

| 項目 | 內容 |
|------|------|
| **優先級** | 🔴 嚴重 |
| **類型** | 功能缺失 |
| **位置** | 五大子系統 |

**問題描述**：
用戶需求明確提到需要「知識管理」系統，但 PRD 中沒有獨立的知識管理模組。

**現有覆蓋**：
- M15 CMS（內容管理）- 僅涵蓋貼文發布
- M08 評價與社交互動
- M10 即時通訊

**缺失功能**：
1. 媒體中心（媒體資產分類）
2. 知識庫分類（文章/教程）
3. 客服系統（工單/在線客服）
4. FAQ / 幫助中心

**影響評估**：
- 知識管理是五大子系統之一，不可遺漏
- 需新增 M18 模組

**建議處理**：
- ✅ 已採納：新增 M18 知識管理模組
- 詳見：[PRD_v0.9_R03_IMPROVEMENT_REPORT.md](PRD_v0.9_R03_IMPROVEMENT_REPORT.md)

---

### 🔴 發現 #2: M12 動態定價優先級矛盾

| 項目 | 內容 |
|------|------|
| **優先級** | 🔴 嚴重 |
| **類型** | 邏輯矛盾 |
| **位置** | §6.9 vs §13.5 |

**問題描述**：
M12 動態定價在不同章節被歸類為不同 Phase：

| 章節 | 歸類 |
|------|------|
| §6.9 M12 動態定價引擎 | Phase 2-A |
| §13.5 MoSCoW | Should Have（Phase 2 後期） |

**根因分析**：
§6.9 說「從 Phase 2 提前至 Phase 2-A」，但 MoSCoW 表沒有相應更新。

**建議處理**：
- ✅ 已採納：用戶確認 M12 為 Phase 1 Must Have
- MoSCoW 表將更新 M12 為 Must Have

---

### 🔴 發現 #3: API 版本策略不一致

| 項目 | 內容 |
|------|------|
| **優先級** | 🔴 嚴重 |
| **類型** | 矛盾 |
| **位置** | §9 vs §15 |

**問題描述**：
不同章節對同一 API 使用不同前綴：

| API | §9 描述 | §15 M05 SDD |
|-----|---------|--------------|
| 訂單 | `/api/orders` | `/api/v1/orders` |
| 預訂 | `/api/v1/bookings` | 統一 |

**建議處理**：
- ✅ 已採納：統一使用 `/api/v2/` 前綴
- 全部 M05 API 更新為 `/api/v2/orders`

| **優先級** | 🟡 中等 |
